# ShellX A12 — Agents and Polish (desktop + CLI + mobile) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the sidebar a trustworthy agent dashboard. One command installs agent hooks safely (`shellx integrations install claude|codex|gemini|opencode`: exact diff, y/n, backup, never clobbers the user's hooks, uninstall restores). Hooks report to ShellX (`shellx agent-event`), and each tab shows Running / Needs input / Idle / Done per agent, with notifications aimed at the pane the agent runs in. After a restart a pane offers "Resume session" (one click, never automatic). Optional pull-request status via `gh`. Plus the A11 leftovers: app language picker, "Check for updates" button, macOS window opacity/blur (gated by a manual check), `shellx tab describe|status`, and an opt-in user command run on agent events.

**Architecture:** Hook → `shellx agent-event AGENT EVENT` (Rust; normalises per agent with fixtures; always exits 0) → one new CLI message `ui.agent.event` → `UiCommandHandler` → `AgentStatusNotifier` (pure reducer, memory only) → sidebar badge / pane header / `LocalSessions.notify` / CLI event bus. Only `(agent, session id)` is persisted, as an optional key of `SavedPane` in `layout.json`. The installer is a pure planner (`text → new text + diff`) over a small dependency-free JSON reader that edits by byte span, plus a line editor for Codex's TOML and a whole-file writer for OpenCode's plugin; the CLI wrapper adds consent, backup and atomic write. Everything else is small, separately tested desktop modules behind existing seams (`settings_schema`, `ConfigFileWriter`, `TrayActions`, `SessionInfo` optional keys).

No new Dart dependencies.

**Spec:** `docs/superpowers/specs/2026-10-07-agents-a12-design.md` (binding; D1–D27 are final, §4 is the copy, §5 privacy/security, §8 Review Focus, §9 the manual checklist). ## Global Constraints

- The spec wins. User-facing strings go in the vi + en ARB files of the app that shows them (desktop `app_en.arb`/`app_vi.arb` + `flutter gen-l10n`; mobile `intl_en.arb`/`intl_vi.arb` + `dart run intl_utils:generate`); "SSH", "tmux", "pane", "tab", "workspace", "hook", agent names, "gh" stay English in Vietnamese copy; keys exactly as spec §4. CLI messages are fixed English sentences (A7 D11); nothing the user wrote is ever echoed (see spec §4.5 for the exact refusal sentences).
- **No new crates, no new Dart packages.** No change to `src/mux/*` except the two constants and caps named in Task 2/16, no change to `daemon_main.dart`, `relay/`. The phone protocol changes only by Task 17's two optional `SessionInfo` keys.
- **Hooks never hurt the agent** (spec D5): `agent-event` exits 0 whatever happens and prints nothing when stdout is not a tty; no shell syntax in any hook command string.
- **The user's files are theirs** (spec D7): the installer writes only after `y`/`--yes`, only the lines it owns, with a backup, atomically, after re-reading to detect a concurrent change; the app itself never writes an agent's config file. The desktop writes the ShellX config file only through A11's `applyKeyEdits` on a user gesture.
- **Untrusted input:** `agent`, `event`, `session`, `message` come from a process the user does not control. The CLI normalises and limits, Dart validates again, a session id enters a command only after `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$` (no quoting needed, cannot start with `-`).
- **Privacy (spec §5):** never log a hook message, session id, path, branch, PR number, `gh` output, the user's hook command, tab description — not under `kDebugMode`. Logs carry an event kind, an agent name from the closed set, an error `runtimeType`, counts, exit codes. `toString()` of every new value class that can hold such data returns `'…'` (a test pins each).
- **One owner per setting** (A11 D4): `agent-resume`, `pr-status`, `agent-event-command`, `background-*` are file keys (read from `ConfigState`, written by `applyKeyEdits`); `app_language`, `agent_command_approved` live in `SettingsStore`; `settings_schema_test` fails on a key with two owners.
- Limits (spec D26): hook stdin 64 KiB; `agent-event` total 2 s; 20 events/s/pane; message 1024; session id 128; hook notices 1 per 5 s per pane; quiet decay 20 s; OSC merge 3 s; PR: 1 at a time, 6/min, 8 s, 120 s refresh, 10 min "none", back-off 5→30 min; user hook: 4 parallel, queue 16, 10 s, 1/s per (pane, event); agent config file ≤ 1 MiB; diff ≤ 5000 lines.
- **Format only the files you touched** (`dart format <files>`, `cargo fmt` only on files you touched; the repo's rustfmt config applies); every task ends green (its tests + the full suite of every package it touched), `flutter analyze lib test` clean, `cargo clippy -- -D warnings` clean for Rust tasks, and a commit containing only the listed files — never `git add -A`.
- Every interface that gains members updates **every** implementer in the same task (`TrayLocalState`, `SettingsStore` fakes, `UrlOpener` fakes, `UiApi`/`UiCommandHandler` fakes in `shellx_agent` tests, `AgentController` fakes).
- Test conventions (A10/A11): widget tests use `pumpConfiguredWorkspace(t)` → `rig.container`, `rig.local.views[paneId].writes`, end with `disposeWorkspace(t, c)`; real file-system and process calls inside `testWidgets` hang under fake async (inject fakes); Rust tests use fakes for the file system, tty and clock (Task 3 defines them) — never touch the real `~`.
- Disk: after a Rust task `rm -rf term/target` if it was created only for this work; same for `apps/*/build` at Task 18.

```rust
pub struct Span { pub start: usize, pub end: usize }          // byte offsets, end exclusive
pub enum Kind { Null, Bool(bool), Num, Str(String), Arr(Vec<Node>), Obj(Vec<Member>) }
pub struct Node { pub kind: Kind, pub span: Span }
pub struct Member { pub key: String, pub key_span: Span, pub value: Node }
#[derive(Debug, PartialEq)] pub enum JsonError { Syntax, TooDeep, TooBig, Duplicate, Comment }

pub fn parse(text: &str) -> Result<Node, JsonError>;           // RFC 8259; ≤ 1 MiB, depth ≤ 64; comments / trailing commas / duplicate keys → error
pub fn get<'a>(obj: &'a Node, key: &str) -> Option<&'a Node>;
pub struct Style { pub indent: String, pub eol: &'static str } // dominant indent (2 spaces default), "\r\n" if the file uses it
pub fn detect_style(text: &str) -> Style;
/// Each returns the whole new text; everything outside the edit is byte-identical.
pub fn insert_member(text: &str, obj: &Node, depth: usize, key: &str, value_json: &str, st: &Style) -> String;
pub fn append_element(text: &str, arr: &Node, depth: usize, value_json: &str, st: &Style) -> String;
pub fn remove_element(text: &str, arr: &Node, index: usize) -> String;
pub fn remove_member(text: &str, obj: &Node, key: &str) -> String;
pub fn render(value: &Json, depth: usize, st: &Style) -> String;  // tiny builder type `Json` for the text WE insert (objects keep insertion order)
pub fn top_level_strings(text: &str) -> Vec<(String, String)>;      // hook payloads: only string members of the root object, each ≤ 4096 bytes
```
