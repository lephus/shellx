# ShellX A11 — Quality Pass P1 (desktop + mobile) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ShellX pleasant for a whole day of use: one Settings surface (7 pages, search, validation, live theme/font preview) over a single source of truth; macOS line-editing keys at the prompt; triple-click and rectangular selection and a vim-key copy mode; reopen a closed tab with its scrollback; focus history back/forward; cursor blink and line height in the config; pinned tabs with a description and a status; move, swap and break panes; find text in every terminal; per-workspace font zoom; a first-run tour, empty-state hints and "What's new"; a global show/hide hotkey; `shellx doctor` and a CLI that opens tabs where the caller lives — and on the phone: the right tab when a notification is tapped while reconnecting, a smarter machine list, per-terminal drafts, an arrow pad and an option to keep the terminal size when the keyboard opens. Optional last: window opacity and blur on macOS.

**Architecture:** Pure, separately tested modules with a thin UI on top, each task shippable alone. Desktop: `config_key_edits.dart` (text edits of the ShellX file), `settings_schema.dart` (one catalogue of every setting with its owner), `setting_validation.dart` (runs the real parser), `SettingsOverlay` + pages (an `A9Overlay`), `settingsPreviewProvider`; `edit_line.dart`, `click_select.dart`, `copy_mode.dart` (pure state machine) + `CopyModeController`; `closed_items.dart` (in-memory ring) over A5a's restore path; `focus_history.dart`; `cursor_blinker.dart`; `tab_meta.dart` in `TerminalTab`/`SavedTab`; `pane_moves.dart` (pure tree ops); `global_search.dart` over A10's `BufferSearch`; `global_hotkey.dart` behind an interface; `tour_state.dart`/`whats_new.dart`. CLI: Rust `doctor` + `fromTab`. Mobile: `pendingSelect`, `unseen` counters, per-tab `draft`, `ArrowPadKey`, `cursorShift`.

**Tech Stack:** Dart ^3.11 / Flutter 3.41.4 via fvm (`~/fvm/versions/3.41.4/bin/dart`, `PATH=~/fvm/versions/3.41.4/bin:$PATH flutter`), `flutter_test`, `package:test`, `fake_async`, flutter_riverpod 3 (desktop), signals + get_it (mobile), xterm 4.0.0 (pinned), Rust (`term/`, `cargo test`). **New dependencies:** desktop `hotkey_manager` (Task 17 only, pinned exactly). ## Prerequisite and how this plan was made

Start `feat/desktop-a11` from `main` (A10 and A5b Task 9 merged). **No task touches `src/mux/*`, `src/agent/*`, `daemon_main.dart`, `agent_side.dart`, `packages/shellx_core` protocol, `shellx_agent`, `shellx_client`, `relay/`** (spec D34). `term/` changes only in Task 15.

This plan was written by **reading the code, not by running scratch copies** (the disk is tight and A10's approach — executing every block — was deliberately not repeated). Code in the steps is therefore **reviewed, not executed**: the first red run of each task is expected to fix small compile details (an import, a parameter name). Where a test needs a number you cannot know (a hex key id in the golden fixture), the step says how to read it from the first failure. Four facts that shaped the design and that the executor should re-confirm in the first minutes:

1. xterm 4.0.0 paints **one cell at a time** (`Painter.paintLine`), so ligatures never form (spec §2: `font-feature` is accepted and does nothing) and changing `TerminalTheme` **clears the paragraph cache** (spec D17: blink must not use the theme).
2. xterm `TerminalKeyboardEvent` has **no meta flag** and ignores Cmd, so ⌘←/⌘⌫ must be window actions (Task 1), not input handlers.
3. `TerminalView.onTapUp` is never called; mouse gestures beyond what xterm routes come from a `Listener` (Tasks 3, 4).
4. `Workspace` in the code is the sidebar **group**; the gap analysis' "workspace" is the **tab** row (Tasks 12–14 follow the code).

## Global Constraints

- The spec wins. User-facing strings go in the vi + en ARB files of the app that shows them (desktop `app_en.arb`/`app_vi.arb` + `flutter gen-l10n`; mobile `intl_en.arb`/`intl_vi.arb` + `dart run intl_utils:generate`); "SSH", "tmux", "pane", "tab", "workspace" stay English in Vietnamese copy; `⌘`/`Ctrl` come from the platform, never a translation. Keys are exactly the ones in spec §4.
- **Phone protocol, relay, agent, daemon unchanged** (spec D34). The mobile "new output" counter is computed on the phone.
- **Privacy (spec §5):** never log terminal text, a search query or snippet, a setting **value**, a tab description, a workspace name, a folder, clipboard text, a draft — not even under `kDebugMode`. Logs carry an event kind, an error `runtimeType`, a config **key name**, a count not tied to a query. `toString()` of every new value class that can hold such data returns `'…'` (a test pins each).
- **The configuration file is the user's** (spec D5, §1 criterion 15): the app writes it only on a user gesture in Settings; `applyKeyEdits` keeps every byte outside the target line (BOM, CRLF, comments, blank lines, other blocks); a damaged managed block refuses the write. Never delete a user's line — comment it out.
- **One owner per setting** (spec D4): file keys are read from `ConfigState` and written to the file; app switches go through `TrayActions.handle(TrayAction)` and the existing providers. `settings_schema_test` fails if a key has two owners.
- **Action recipe** (every new keybindable action, Tasks 1, 4, 5, 6, 9, 11, 12, 13, 14, 16): (1) `ActionSpec` in `kActionSpecs` (`keybind_actions.dart`; `repeats`, `param`, `paramHint`; `inPalette` defaults to true); (2) a case in `intentForAction` and, if it has data, in `describeIntent`; (3) the `Intent` class in `ui/terminal/terminal_intents.dart`; (4) the `Action` in `terminal_workspace_page.dart` (`actionsMap`, via `run<I>(body, enabled:)`) or in the `WorkspaceConfig` mixin; (5) the default chord(s) in `defaultKeyBindings` (`keybindings.dart`) — Windows uses **left Alt only** (A3 D20, A9 D26) and `shifted()` is Ctrl+Shift there, so a "Cmd+Shift+X" mac chord needs an explicit Ctrl+Shift+Alt+X Windows chord when Ctrl+Shift+X is taken; (6) a label in `ui/config/action_labels.dart` and ARB key `action<Name>` (en + vi), then `PATH=~/fvm/versions/3.41.4/bin:$PATH flutter gen-l10n`; (7) golden: add the new chord lines to `a11Additions` (or `a11Changes`) in `test/ui/shortcut_golden_test.dart` — run the test once, copy the "extra" lines from the failure output (they contain hex key ids you cannot guess), never regenerate the frozen fixtures; (8) the command palette and `ShortcutsSheet` pick the action up by themselves.
- Limits: settings write debounce 300 ms (slider commits on release); description ≤ 120 graphemes; closed-items ≤ 10 entries / 2 MiB text; focus history ≤ 50; global search ≤ 200 rows (≤ 20 per pane), snippet ≤ 120 chars, query ≥ 2 chars, debounce 150 ms, slice 8 ms; copy-mode page = viewport rows; workspace zoom −6…+10 pt; blink 530 ms; adjust-cell-height −10…50 %; opacity 0.3–1; mobile arrow pad threshold 14 dp, rates 4/10/20 per second; pending select 30 s; draft debounce 200 ms.
- **Format only the files you touched** (`dart format <files>`); every task ends green (its tests + the full suite of every package it touched), `dart format --set-exit-if-changed` on its files, `flutter analyze lib test` clean, and a commit containing only the listed files — never `git add -A`.
- Every interface that gains members updates **every** implementer in the same task (`KeyAction` consumers, `TrayLocalState`, `SettingsStore` fakes, `UrlOpener`, `ConfigFileStore` fakes).
- Test conventions (from A10): widget tests that tap with xterm's detector end with `pump(const Duration(milliseconds: 400))`; a mouse click is `tapAt(p, kind: PointerDeviceKind.mouse)`; real file-system calls inside `testWidgets` hang under fake async (inject fakes); the shared UI harness is `pumpConfiguredWorkspace(t)` → `rig.container`, `rig.local.views[paneId].writes/.resizes`, finished with `disposeWorkspace(t, c)` (see `test/ui/pane_find_test.dart`); macOS-only shortcut tests use `variant: TargetPlatformVariant.only(TargetPlatform.macOS)`.

## Review Focus

1. **Settings corrupt or surprise-write the user's file** — a lost comment, changed line endings, a deleted user line on reset, a write when a page is merely opened, a write over a hand edit. Pinned by `config_key_edits_test` (property: every byte outside the target line unchanged, CRLF and BOM kept), `settings_overlay_test` ("opening writes nothing", "hand edit meanwhile → refused, reloaded") (Tasks 8, 9).
2. **Two sources of truth** — one setting reachable from both the tray and Settings with different values, or a key in both stores. Pinned by `settings_schema_test` (each key exactly one owner; every `TrayAction` switch has exactly one Settings row) and `settings_agents_test` (a toggle calls `TrayActions.handle` with the same action the tray uses) (Tasks 8, 9).
3. **A GUI value the loader rejects** — Settings accepts what `buildShellxConfig` flags, leaving the file red. Pinned by `setting_validation_test` (uses the real builder) and a round-trip test over every schema entry (write → `buildShellxConfig` → the same value, no problems) (Task 8).
4. **Preview leaks** — a hover writes the file or changes a real pane; Esc keeps the preview. Pinned by `settings_preview_test` (Task 10).
5. **`edit_line` reaches vim** (Ctrl-A increments a number) or an exited pane. Pinned by `edit_line_test` ("alt buffer → not enabled") and the widget test with `writes` (Task 1).
6. **Copy mode swallows the wrong keys or sticks** — keys leaking to the program, stuck after the pane closes or the tab changes, dead on Telex/Hangul layouts. Pinned by `copy_mode_state_test`, `copy_mode_ui_test` ("every key is swallowed", "exits when the pane exits", "physical key wins over the character") (Task 4).
7. **The closed-items ring leaks or grows** — writes to disk, exceeds 10 / 2 MiB, keeps a `Terminal`. Pinned by `closed_items_test`, `reopen_closed_ui_test` ("nothing new on disk") (Task 5).
8. **Reopen duplicates a session, lands in the wrong workspace or steals focus**; `layout.json` with the new keys breaks an old reader or a new reader of an old file. Pinned by `terminal_tabs_restore_test` additions, `restore_snapshot_meta_test` (both directions, unknown keys) (Tasks 5, 13).
9. **Blink burns CPU or fights the program's cursor** (`ESC[?25l`). Pinned by `cursor_blinker_test` (stops when unfocused, `wants` respected, ≤ 2 notifications per second) (Task 7).
10. **A pane move orphans a session** (the shell runs with no pane) or closes one. Pinned by `pane_moves_test` (the multiset of session ids before = after) (Task 12).
11. **The global hotkey leaks a registration or fires inside the app's own typing.** Pinned by `GlobalHotkey` interface fakes (`unregisterAll` on dispose; a refused registration → a problem, not a crash); ⚠ manual (Task 17).
12. **The CLI opens a tab in the user's workspace or steals focus.** Pinned by the Rust tests (`fromTab` present only without `--workspace`) and `ui_command_handler_test` (`focus` false by default) (Task 15).
13. **Mobile: `pendingSelect` selects after the user chose; "new output" never clears; a draft leaks across tabs; a keyboard still sends `resize` with the fixed-height option on.** Pinned by `pending_select_test`, `unseen_output_test`, `draft_test`, `terminal_fixed_height_test` (Tasks 2, 18, 20, 21).
14. **Privacy** — a log-capture test per feature (`debugPrint` captured, test strings absent) is part of each task's checklist.
15. **Accessibility** — Settings/tour/search overlays: labelled, focus trapped, Esc closes, focus returns; status dots have text; the arrow pad has semantic actions.

```dart
Future<void> chord(
  WidgetTester t,
  LogicalKeyboardKey key, {
  bool meta = false,
  bool alt = false,
}) async {
  if (meta) await t.sendKeyDownEvent(LogicalKeyboardKey.metaLeft);
  if (alt) await t.sendKeyDownEvent(LogicalKeyboardKey.altLeft);
  await t.sendKeyEvent(key);
  if (alt) await t.sendKeyUpEvent(LogicalKeyboardKey.altLeft);
  if (meta) await t.sendKeyUpEvent(LogicalKeyboardKey.metaLeft);
  await t.pump();
}

void main() {
  testWidgets('⌘← ⌘→ ⌘⌫ ⌥⌫ write the shell keys to the focused pane', (t) async {
    final rig = await pumpConfiguredWorkspace(t);
    final c = rig.container;
    final tab = c.read(terminalTabsProvider).selected!;
    final writes = rig.local.views[tab.focusedPaneId]!.writes;
    writes.clear();
    await chord(t, LogicalKeyboardKey.arrowLeft, meta: true);
    await chord(t, LogicalKeyboardKey.arrowRight, meta: true);
    await chord(t, LogicalKeyboardKey.backspace, meta: true);
    await chord(t, LogicalKeyboardKey.backspace, alt: true);
```

```dart
import 'package:flutter/gestures.dart';
import 'package:flutter/services.dart';
import 'package:flutter/widgets.dart';
import 'package:xterm/xterm.dart';

const int kMaxLogicalRowsSelect = 256;

class ClickCounter {
  ClickCounter({this.window = kDoubleTapTimeout, this.slop = kDoubleTapSlop});
  final Duration window;
  final double slop;
  Offset? _at;
  Duration? _time;
  int _count = 0;

  int register(Offset p, Duration time) {
    final near = _at != null &&
        _time != null &&
        time - _time! <= window &&
        (p - _at!).distance <= slop;
    _count = near && _count < 3 ? _count + 1 : 1;
    _at = p;
    _time = time;
    return _count;
  }

  void reset() {
    _count = 0;
    _at = null;
    _time = null;
  }
}

({int first, int last}) logicalLineRange(Buffer b, int row) {
  final lines = b.lines;
  var first = row.clamp(0, lines.length - 1);
  while (first > 0 && lines[first].isWrapped && row - first < kMaxLogicalRowsSelect) {
    first--;
  }
  var last = row.clamp(0, lines.length - 1);
  while (last + 1 < lines.length &&
      lines[last + 1].isWrapped &&
      last - first < kMaxLogicalRowsSelect) {
    last++;
  }
  return (first: first, last: last);
}

bool get _altDown {
  final k = HardwareKeyboard.instance.logicalKeysPressed;
  return k.contains(LogicalKeyboardKey.altLeft); // Windows: left Alt only (A3 D20)
}

/// A11 D12. xterm 4.0.0 gives double-click and drag; this adds the third
/// click (a logical line) and ⌥/Alt-drag (a rectangle) from a [Listener]
/// outside the gesture arena — like the link layer, because the arena
/// never reports a third tap.
class ClickSelectLayer extends StatefulWidget {
  const ClickSelectLayer({
    super.key,
    required this.terminal,
    required this.controller,
    required this.viewKey,
    required this.child,
  });
  final Terminal terminal;
  final TerminalController controller;
  final GlobalKey<TerminalViewState> viewKey;
  final Widget child;

  @override
  State<ClickSelectLayer> createState() => _ClickSelectLayerState();
}

class _ClickSelectLayerState extends State<ClickSelectLayer> {
  final _counter = ClickCounter();

  void _down(PointerDownEvent e) {
    if (e.kind != PointerDeviceKind.mouse || e.buttons != kPrimaryButton) return;
    // A program that owns the mouse keeps it unless ⌥ is held (iTerm2 rule).
    final altHeld = _altDown;
    final mouseApp = widget.terminal.mouseMode != MouseMode.none;
    if (mouseApp && !altHeld) {
      _counter.reset();
      return;
    }
    widget.controller.setSelectionMode(
      altHeld ? SelectionMode.block : SelectionMode.line,
    );
    final n = _counter.register(e.localPosition, e.timeStamp);
    if (n != 3) return;
    final render = widget.viewKey.currentState?.renderTerminal;
    if (render == null) return;
    final cell = render.getCellOffset(e.localPosition);
    final range = logicalLineRange(widget.terminal.buffer, cell.y);
    // After xterm's own double-tap selection ran for this pointer-down.
    WidgetsBinding.instance.addPostFrameCallback((_) {
      if (!mounted) return;
      final b = widget.terminal.buffer;
      widget.controller.setSelection(
        b.createAnchorFromOffset(CellOffset(0, range.first)),
        b.createAnchorFromOffset(
          CellOffset(widget.terminal.viewWidth, range.last),
        ),
        mode: SelectionMode.line,
      );
    });
    WidgetsBinding.instance.ensureVisualUpdate();
  }

  @override
  Widget build(BuildContext context) => Listener(
    behavior: HitTestBehavior.translucent,
    onPointerDown: _down,
    child: widget.child,
  );
}
```

```dart
    required this.launch,
    required this.text,
    required this.label,
  });

  final String? cwd;

  final String label;

  int get textBytes => text.length;

  bool get isWorthKeeping => text.isNotEmpty || cwd != null || launch != null;

class ClosedItems {
  ClosedItems({this.maxItems = 10, this.maxBytes = 2 * 1024 * 1024});
  final int maxItems;
  final int maxBytes;
  final List<ClosedItem> _items = []; // oldest first

  int get length => _items.length;
  int get totalBytes => _items.fold(0, (n, i) => n + i.textBytes);
  ClosedItem? peek() => _items.isEmpty ? null : _items.last;
  ClosedItem? pop() => _items.isEmpty ? null : _items.removeLast();
  void clear() => _items.clear();

  void push(ClosedItem item) {
    if (!item.isWorthKeeping) return;
    _items.add(item.textBytes > maxBytes ? item.withoutText() : item);
    while (_items.length > maxItems) {
      _items.removeAt(0);
    }
    while (totalBytes > maxBytes && _items.length > 1) {
      _items.removeAt(0);
    }
  }
```

```dart
import 'config_writer.dart';

const kSettingsStart = '# >>> shellx-managed settings >>>';
const kSettingsEnd = '# <<< shellx-managed settings <<<';
const _blockNote = '# Written by ShellX Settings. Edit freely; delete the block to forget it.';

sealed class KeyEdit {
  const KeyEdit(this.key);
  final String key;
  @override
  String toString() => '…';
}

final class SetKey extends KeyEdit {
  const SetKey(super.key, this.value);
  final String value;
}

final class ResetKey extends KeyEdit {
  const ResetKey(super.key, {this.explicitDefault = false});
  final bool explicitDefault;
}

String applyKeyEdits(String text, List<KeyEdit> edits) {
  var out = text;
  for (final e in edits) {
    out = switch (e) {
      SetKey() => _set(out, e.key, e.value),
      ResetKey() => _reset(out, e),
    };
  }
  return out;
}

/// Regions the edits must not treat as the user's lines.
({int start, int end})? _block(List<ConfigLineSpan> lines, String start, String end) {
  final s = <int>[], e = <int>[];
  for (var i = 0; i < lines.length; i++) {
    final b = lines[i].body.trim();
    if (b == start) s.add(i);
    if (b == end) e.add(i);
  }
  if (s.isEmpty && e.isEmpty) return null;
  if (s.length == 1 && e.length == 1 && s.single < e.single) {
    return (start: s.single, end: e.single);
  }
  throw const ConfigWriteRefused(ConfigWriteRefusal.damagedBlock);
}

String? _keyOf(String body) {
  final t = body.trim();
  if (t.isEmpty || t.startsWith('#')) return null;
  final eq = t.indexOf('=');
  return eq < 0 ? null : t.substring(0, eq).trim();
}

String _set(String text, String key, String value) {
  final lines = splitConfigLines(text);
  final mine = _block(lines, kSettingsStart, kSettingsEnd);
  final keys = _block(lines, kManagedStart, kManagedEnd); // validates it too
  bool inside(int i) =>
      (mine != null && i >= mine.start && i <= mine.end) ||
      (keys != null && i >= keys.start && i <= keys.end);
  final eol = eolBefore(text, lines, mine?.start ?? lines.length);
  // 1. A user line outside both blocks: edit the last in place.
  for (var i = lines.length - 1; i >= 0; i--) {
    if (!inside(i) && _keyOf(lines[i].body) == key) {
      final span = lines[i];
      final raw = text.substring(span.start, span.end);
      final indent = raw.substring(0, raw.length - raw.trimLeft().length);
      final ending = raw.endsWith('\r\n') ? '\r\n' : (raw.endsWith('\n') ? '\n' : '');
      return text.replaceRange(span.start, span.end, '$indent$key = $value$ending');
    }
  }
  // 2. Our block.
  final newLine = '$key = $value';
  if (mine != null) {
    for (var i = mine.start + 1; i < mine.end; i++) {
      if (_keyOf(lines[i].body) == key) {
        final raw = text.substring(lines[i].start, lines[i].end);
        final ending = raw.endsWith('\r\n') ? '\r\n' : '\n';
        return text.replaceRange(lines[i].start, lines[i].end, '$newLine$ending');
      }
    }
    return text.replaceRange(lines[mine.end].start, lines[mine.end].start, '$newLine$eol');
  }
  final head = text.isEmpty || text.endsWith('\n') ? text : '$text$eol';
  final sep = head.isEmpty || head.endsWith('$eol$eol') ? '' : eol;
  return '$head$sep$kSettingsStart$eol$_blockNote$eol$newLine$eol$kSettingsEnd$eol';
}

String _reset(String text, ResetKey r) {
  final lines = splitConfigLines(text);
  final mine = _block(lines, kSettingsStart, kSettingsEnd);
  final keys = _block(lines, kManagedStart, kManagedEnd);
  bool inside(int i) =>
      (mine != null && i >= mine.start && i <= mine.end) ||
      (keys != null && i >= keys.start && i <= keys.end);
  final b = StringBuffer();
  var touched = false;
  for (var i = 0; i < lines.length; i++) {
    final raw = text.substring(lines[i].start, lines[i].end);
    if (mine != null && i > mine.start && i < mine.end && _keyOf(lines[i].body) == r.key) {
      touched = true; // drop our own line
      continue;
    }
    if (!inside(i) && _keyOf(lines[i].body) == r.key) {
      final indent = raw.substring(0, raw.length - raw.trimLeft().length);
      b.write('$indent# ${raw.trimLeft()}');
      touched = true;
      continue;
    }
    b.write(raw);
  }
  var out = touched ? b.toString() : text;
  out = _dropEmptyBlock(out);
  return r.explicitDefault ? _set(out, r.key, '').replaceFirst('${r.key} = \n', '${r.key} =\n') : out;
}

String _dropEmptyBlock(String text) {
  final lines = splitConfigLines(text);
  final blk = _block(lines, kSettingsStart, kSettingsEnd);
  if (blk == null) return text;
  for (var i = blk.start + 1; i < blk.end; i++) {
    final t = lines[i].body.trim();
    if (t.isNotEmpty && t != _blockNote) return text;
  }
  return text.replaceRange(lines[blk.start].start, lines[blk.end].end, '');
}
```

```dart
sealed class SettingsWrite { const SettingsWrite(); }
final class Saved extends SettingsWrite { const Saved(); }
final class Invalid extends SettingsWrite { const Invalid(this.problem); final ConfigProblem problem; }
final class Refused extends SettingsWrite { const Refused(this.why); final ConfigWriteRefusal why; }
final class Changed extends SettingsWrite { const Changed(); }

class SettingsWriter {
  SettingsWriter(this._ref);
  final Ref _ref;
  Future<SettingsWrite> set(SettingDef def, String raw) async {
    final key = def.fileKey!;
    final paths = _ref.read(configPathsProvider);
    final check = validateSetting(key, raw, macos: _mac, home: paths.home, windows: paths.windows);
    if (!check.ok) return Invalid(check.problem!);
    return _write(paths, (t) => applyKeyEdits(t, [SetKey(key, raw.trim())]));
  }
  Future<SettingsWrite> reset(SettingDef def) {
    final state = _ref.read(shellxConfigProvider);
    final paths = _ref.read(configPathsProvider);
    final src = settingSource(def, state, paths);
    return _write(paths, (t) => applyKeyEdits(t, [ResetKey(def.fileKey!, explicitDefault: src is GhosttySource)]));
  }
  Future<SettingsWrite> resetAll() =>
      _write(_ref.read(configPathsProvider), removeSettingsBlock);
  Future<SettingsWrite> _write(ConfigPaths paths, String Function(String) f) async {
    try {
      await _ref.read(configFileWriterProvider).editText(paths.shellx, f, template: shellxTemplate(_ref.read));
    } on ConfigWriteRefused catch (e) {
      if (e.reason == ConfigWriteRefusal.changed) {
        await _ref.read(shellxConfigProvider.notifier).load();
        return const Changed();
      }
      return Refused(e.reason);
    } on Object catch (e) {
      debugPrint('ShellX: setting not saved: ${e.runtimeType}'); // never the key's value
      return const Refused(ConfigWriteRefusal.unreadable);
    }
    await _ref.read(shellxConfigProvider.notifier).load(ownWrite: true);
    return const Saved();
  }
}
```
