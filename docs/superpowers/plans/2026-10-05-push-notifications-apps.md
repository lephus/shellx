- **Not touched:** `relay/`, `term/`, `packages/shellx_agent` (N-a still owns them).

## Goal

Phones paired with a computer receive the agent's notifications, also when the app is closed; tapping one opens that computer (and the tab, when it is open). The desktop app lets the user pick the long-command threshold and actually turns N-a's detection on. The privacy policy says what push sends where.

### 2. Platform setup
- Android: `POST_NOTIFICATIONS` permission; default channel `shellx_notifications` created in `MainActivity` (name from `strings.xml`, vi/en) and named in the FCM `default_notification_channel_id` meta-data; small icon `@drawable/ic_notification` (white glyph, generated by `tool/gen_app_icons.py` from the monochrome layer) and accent colour meta-data.
- iOS: `Runner/Runner.entitlements` with `aps-environment` = `development`, `CODE_SIGN_ENTITLEMENTS` on the Runner target's three configurations, `SystemCapabilities` `com.apple.Push` + `com.apple.BackgroundModes`, `UIBackgroundModes` = `remote-notification`.
- Test: `platform_config_test.dart` checks each of these.

### 3. Mobile: backend port and sign-out
- `ShellxBackend.registerPushToken(token, platform)` (ClientBackend: `ShellxApi.registerPushToken`, refused after dispose like other REST calls); `FakeBackend` records calls.
- `SessionHolder` sign-out (`loggedOut`): `DELETE /v1/devices/me/push-token` together with `POST /v1/auth/logout`, both inside the existing 10 s bound, errors swallowed.
- Tests: client_backend test (PUT body, refused after dispose); session_holder test (logout sends both requests; offline still signs out).

### 4. Mobile: notifications feature (`lib/features/notifications/`)
- `domain/push_messaging.dart`: port `PushMessaging` (permission, request, token, token refreshes, foreground / opened / initial messages, delete token), `PushPermission`, `PushMessage` (+ `agentId`, `sessionId` from `data`), `UnavailablePushMessaging` (Firebase missing).
- `data/firebase_push_messaging.dart`: `Firebase.initializeApp` in a try (bounded); any failure → `UnavailablePushMessaging`. iOS waits briefly for the APNs token before `getToken`. Registered by the DI module (`@preResolve`).
- `presentation/push_controller.dart` (`PushController`, lazy singleton):
  - per signed-in backend: reads the permission; when granted, gets the token and registers it (errors → next launch); `onTokenRefresh` re-registers;
  - `onPairedMachines(n)` (machine list after a refresh): with n ≥ 1 and never asked before on this phone (`push_permission_asked` in SharedPreferences), asks once; denial is never asked again automatically;
  - sign-out (backend → null): deletes the local FCM token (best effort);
  - foreground message → `PopupHandler.showInfo(title, body)`, tapping the banner opens it;
  - `getInitialMessage` (after the first frame) / `onMessageOpenedApp` → `NotificationOpener`;
  - `permission` signal and `refreshPermission()` / `requestFromSettings()` for Settings.
- `presentation/notification_opener.dart`: signed in and the machine pinned → select the tab whose session id matches (when open), then show the terminal page of that machine unless it is already on top (`MachineNavigator`, implemented over `AppRouter`: back to the machine list, push `TerminalRoute`; the name from `GET /v1/devices`, bounded).
- Wiring: `RootApp` starts the controller; `MachineListController` reports the paired count.
- Tests (fakes for `PushMessaging`, backend, navigator): permission asked once after a paired machine, never without one, never again after denial; token registered when granted, re-registered on refresh, not when signed out, retried on the next sign-in after a failure; sign-out deletes the local token; foreground banner; tap opens machine + tab, ignores unknown machine / signed out; unavailable messaging does nothing.
