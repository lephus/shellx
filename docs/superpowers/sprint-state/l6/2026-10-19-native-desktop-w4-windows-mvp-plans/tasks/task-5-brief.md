# Task 5: TermCore over a PtyLink, local ConPTY link, embedded fonts, §7.4 terminal palette

Binding constraints: `../constraints.md`. Crate: `windows/shellx-app` (Task 1 promoted the spike: `src/{main.rs, session.rs, smoke.rs, app.rs}`). Model crate API you use: `shellx_model::palette::{TERM_BG, TERM_FG, TERM_CURSOR, ANSI, Rgba}`, `shellx_model::paste::encode_paste(text, bracketed) -> Vec<u8>`.

Split the spike's `Session` into a byte-link-agnostic `TermCore` (shared by local and, later, remote panes) and a ConPTY `LocalPty` link; apply the §7.4 terminal palette; embed and register fonts; extend `--smoke`. Local and remote panes must differ ONLY in their `PtyLink`.

## term_core.rs
- `pub trait PtyLink: Send + Sync { fn write(&self, bytes: &[u8]); fn resize(&self, cols: u16, rows: u16, cell_w_px: u32, cell_h_px: u32) -> anyhow::Result<()>; fn is_closed(&self) -> bool; }` — `&self` so the libghostty `on_pty_write` callback (query replies: DSR/DA) can hold an `Arc<dyn PtyLink>`.
- `pub struct TermCore { terminal, render, encoder, link: Arc<dyn PtyLink>, cols, rows }` with: `new(link, cols, rows) -> Result<TermCore>` (creates Terminal with SCROLLBACK 10 MiB, `on_pty_write` → `link.write`, applies the palette: `set_default_colors(TERM_FG, TERM_BG, TERM_CURSOR)` and `set_default_palette` with ANSI 0–15 = `shellx_model::palette::ANSI`, 16–255 untouched/None), `feed(&mut self, bytes)`, `send_text(&mut self, text)` (scroll to bottom, write UTF-8 as ONE write), `send_chord(&mut self, chord) -> bool`, `encode_chord`, `paste(&mut self, text)` (bracketed iff `terminal.mode(2004, false)`; one write of `encode_paste(text, bracketed)`; scroll to bottom), `bracketed_paste(&self) -> bool`, `resize(cols, rows, cell_w, cell_h)` (VT then link, min 2×1, no-op when unchanged), `size()`, `scroll_lines`, `title`, `frame`, `text_lines`, `selection_text(start, end)` passthrough to `Terminal::selection_text` (Task 9 uses it), `link_closed() -> bool`.
- Keep the spike's behavior (scroll-to-bottom on input, resize clamping) exactly.
- Unit tests in `term_core.rs` with a `FakeLink` (records writes, resize calls): `palette_applied` (render default colors == TERM_BG/TERM_FG; palette index 4 == PRIMARY), `paste_is_bracketed_only_when_mode_2004_set` (feed `"\x1b[?2004h"` then paste `"a\nb"` → one write `"\x1b[200~a\rb\x1b[201~"`; after `"\x1b[?2004l"` → `"a\rb"`), `send_text_is_one_utf8_write` (`"tiếng Việt"` → exactly one write of bytes `74 69 e1 ba bf 6e 67 20 56 69 e1 bb 87 74`), `resize_reaches_link_once`, `query_reply_goes_to_link` (feed DSR `"\x1b[6n"` → link receives a CPR `"\x1b[…R"`).
  These need libghostty-vt (Zig). They run in CI on Windows via `--smoke`-independent `cargo test -p shellx-app --lib --release --locked --target $TARGET term_core` ONLY if that does not double the GPUI build time; otherwise run them on the Mac: the shellx-app crate has GPUI only under `cfg(windows)`, so on macOS `cargo test -p shellx-app --lib term_core` builds only ghostty-vt + cmux-pty. To do that on the Mac: `git submodule update --init ghostty --reference ~/Documents/myProjects/shellx-pro/ghostty` (from the worktree root; check `df -h /` first, keep ≥ 15 GB), Zig is at `~/.local/zig-0.16.0` (on PATH via ~/.zprofile; `export PATH=$HOME/.local/zig-0.16.0:$PATH` if not). Decide which and say why in the report; the Mac route is preferred. Never build shellx-app's UI (GPUI) on the Mac — it is cfg(windows) and will not compile there anyway.
