- `src/os_info.rs`: `os_version()` → e.g. `"10.0.26100"` from `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` (`CurrentMajorVersionNumber`, `CurrentMinorVersionNumber`, `CurrentBuildNumber`) via the `winreg` crate (MIT) under `cfg(windows)`, `"unknown"` elsewhere; `device_name()` = `COMPUTERNAME` env (fallback "PC Windows").
- `shellx-model/src/account.rs` (new, pure): `AccountState { Unknown, LoggedOut, LoggingIn, LoggedIn { machine_id: String }, Error(CoreErr) }` + `pub struct AccountFlow` event/action machine like `remote_state.rs`: events `Started`, `ListResult(Result<Vec<MachineInfo>, CoreErr>)`, `LoginSubmitted{email,password}`, `LoginResult(Result<LoginInfo,CoreErr>)`, `Registered(Result<Registered,CoreErr>)`, `Tick(now_ms)`, `LogoutRequested`, `LoggedOut`; actions `CallList`, `CallLogin{email,password}`, `CallRegister`, `CallHeartbeat`, `CallLogout`, `ScheduleTick{at_ms}`. Rules: on start → `CallList`; `not_logged_in` error → LoggedOut; list OK without `is_this_machine` → `CallRegister` (once); list OK with it → LoggedIn; heartbeat every 30 000 ms, list every 15 000 ms while LoggedIn; a network error keeps the last machine list and retries on the next tick (offline must not log the user out). Tests with FakeCore-shaped results (name: `not_logged_in_shows_login`, `login_then_register_once`, `heartbeat_every_30s_list_every_15s`, `network_error_keeps_session`). The password is held only in the `LoginSubmitted` event → `CallLogin` action and dropped after the call (never stored in state, never logged; zeroize not required).
- UI (`cfg(windows)`): `ui/text_field.rs` adapted from GPUI `examples/input.rs` (Apache-2.0: header comment naming its origin) with a `masked` option; `ui/login.rs`: card in the sidebar machines area when LoggedOut: `Str::NotLoggedIn` + primary button `Str::Login` → panel with Email, Mật khẩu (masked), primary button Đăng nhập, error line in ERROR with `Str::LoginFailed` + the core message; Enter submits; Esc closes. All core calls run off the UI thread (`cx.background_spawn`), results applied with `entity.update`.
