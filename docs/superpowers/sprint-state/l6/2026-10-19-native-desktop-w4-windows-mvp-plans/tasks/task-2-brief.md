## keys.rs  (Windows Terminal conventions)
- Input: `pub struct KeyIn<'a> { pub key: &'a str /* GPUI key name: "a", "c", "enter", "tab", "left", "f5", "=", "-", "+", "_", "insert", "pageup", "," … */, pub ctrl: bool, pub alt: bool, pub shift: bool, pub win: bool }` and context `pub struct KeyCtx { pub has_selection: bool, pub composing: bool }`.
- Output `#[derive(Debug, PartialEq, Eq)] pub enum KeyAction { App(AppCommand), Chord(String), Text /* let the IME/WM_CHAR path deliver it */, Ignore }` and `pub enum AppCommand { Copy, Paste, NewTab, ClosePane, NextTab, PrevTab, SplitRight, SplitDown, FocusPane(Dir), ToggleSidebar, OpenSettings }`, `pub enum Dir { Left, Right, Up, Down }` (Dir is shared with layout.rs later — define it in keys.rs and re-export from lib.rs; Task 3 imports it).
- `pub fn map_key(k: &KeyIn, ctx: &KeyCtx) -> KeyAction`, in this order:
  1. `ctx.composing` → Ignore (the IME owns keys). `k.win` → Ignore.
  2. App bindings: Ctrl+Shift+C → Copy; Ctrl+C (no shift/alt) with `has_selection` → Copy; Ctrl+Shift+V → Paste; Shift+Insert (no ctrl/alt) → Paste; Ctrl+Shift+T → NewTab; Ctrl+Shift+W → ClosePane; Ctrl+Tab → NextTab; Ctrl+Shift+Tab → PrevTab; Ctrl+PageDown → NextTab; Ctrl+PageUp → PrevTab; Alt+Shift+("=" | "+") → SplitRight; Alt+Shift+("-" | "_") → SplitDown; Alt+arrow (no ctrl/shift) → FocusPane(dir); Ctrl+Shift+B → ToggleSidebar; Ctrl+"," → OpenSettings. Letter keys compare case-insensitively ("C" == "c").
  3. Ctrl+Alt together (AltGr) and not matched above → Text.
  4. Named key (enter, backspace, tab, escape, up, down, left, right, home, end, pageup, pagedown, insert, delete, space when ctrl/alt held, f1–f24) or any key with ctrl or alt → `Chord` in the libghostty chord grammar `"ctrl+alt+shift+<key>"` (modifier order ctrl, alt, shift; key lowercase), e.g. Ctrl+C without selection → `Chord("ctrl+c")`, Ctrl+V → `Chord("ctrl+v")`, Shift+Tab → `Chord("shift+tab")`, Enter → `Chord("enter")`.
  5. Otherwise → Text.
- Tests (name them): `ctrl_c_copies_only_with_selection`, `ctrl_v_goes_to_shell`, `ctrl_shift_v_and_shift_insert_paste`, `altgr_is_text`, `composing_ignores_everything`, `split_and_focus_bindings`, `named_keys_become_chords`, `plain_letters_are_text`.

## paste.rs  (Review Focus 2)
- `pub fn encode_paste(text: &str, bracketed: bool) -> Vec<u8>`:
  1. Normalize newlines: `"\r\n"` → `"\r"`, lone `"\n"` → `"\r"`.
  2. Remove every `"\x1b[200~"` and `"\x1b[201~"`, repeating until none remain (removal can splice a new marker together, e.g. `"\x1b[20\x1b[201~1~"` → must not leave `"\x1b[201~"`).
  3. If `bracketed`: return `ESC[200~` + text + `ESC[201~`; else the text bytes. Empty input → empty output (no markers even when bracketed).
- Tests: `paste_strips_embedded_markers` (input `"echo hi\x1b[201~rm -rf ~\n"` bracketed → exactly `"\x1b[200~echo hi" + "rm -rf ~\r" + "\x1b[201~"`, and the output contains `\x1b[201~` exactly once, at the end), `paste_strips_spliced_markers` (the splice case above), `paste_normalizes_newlines`, `paste_unbracketed_has_no_markers`, `paste_empty_is_empty`, `paste_keeps_utf8` (`"tiếng Việt"` bytes unchanged).
