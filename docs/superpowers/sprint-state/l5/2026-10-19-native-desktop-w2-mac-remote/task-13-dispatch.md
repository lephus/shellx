## Behaviour decisions (so you do not guess)
- Signed-in detection at launch: after `config.set`, call `machines.list`; error code `not_logged_in` (or `unauthorized`) -> `isSignedIn = false`, host not started, only `signIn` proceeds. Any 401-class error mid-session flips `isSignedIn = false` and stops host + links. Network errors (`network`, timeouts, 5xx) NEVER flip it: keep the last `machines`, keep timers running, show nothing blocking (Review Focus 2). Test `apiDownKeepsLastMachinesAndRecovers`.
- Timers use the injected `RemoteClock` (`sleep(until:)`), one task per timer, never overlapping calls of the same timer: heartbeat 30 s, `machines.list` 15 s (also feeds each client supervisor's `machineAvailability(online:lastSeen:)`), `pair.pending` 5 s, outgoing `pair.poll` 2 s per waiting pairing (stop at 300 s -> `.expired`), enroll-pending poll 1 s only while the gate holds expectations.
- `machines` excludes `is_this_machine`; each `RemoteMachine.access` = `.granted` if a `RemoteLinkRecord` exists for it, `.requested(pairingID:code:)` while an outgoing pairing is waiting, else `.none`; `link` = latest state of its client supervisor (else `.idle`). Persist records in `RemoteLinkStore(paths:)`; load them at startup and re-create client supervisors for enrolled ones (started without invite; they only run while the machine is online).
- `pendingApprovals`: from `pair.pending`; `requesterName` from the machines list by `from_machine_id` (fallback to its id); `firstSeen` = first poll that saw it; entries older than 300 s are dropped.
- `approve(id)` order (brief): refuse suspicious -> `tickets.mint {permission:"connect", target_machine_id:<this machine id>, write_to:"invite-connect.ticket"}` -> `run(enrollCreate(... ttlSeconds: 300))` (stdout = invite URI; never log it, never put it in argv of anything else; it goes to `pair.approve` through the core's JSON only) -> `InviteURI.summary` -> `pair.approve {pairing_id, invite_uri, fingerprint}` -> `gate.expect(invitationID:pairingID:now)`; then the enroll-pending poller approves ONLY ids the gate returns `.approve` for and denies every other pending id (`unknownPendingEnrollmentIsDenied`). If any step after `enrollCreate` fails, run `enrollDeny` for that invitation id.
- `deny(id)`: `pair.deny`, remove from `pendingApprovals`. Errors are logged by code only.
- `requestAccess`: returns the 6-digit `code` from `pair.request`; `OutgoingPairing.ownFingerprint` = the `fingerprint` field of `pair.request`'s response (K3 D5). On `approved`: save record `{machineID, route: relay_route, slot: relay_slot, daemonFingerprint, enrolled: false}`, start the client supervisor with `invite_path` as invite file.
- `openSession(on:)` uses `RemoteCommandLine`; add the missing argv builders there (pure functions, package tests): `terminalList(clientSocket:)` = `["--socket", <sock>, "terminal", "list", "--json"]` and `workspaceCreate(clientSocket:name:)`. Wait for `.connected` at most 20 s on the injected clock, else throw `ShellXCoreError(code: "offline", ...)`.
- `stopForTermination()` is synchronous and returns within 2 s even if a launcher call hangs: cancel timers, `stop()` client links, `stop()` daemon (includes `server stop`), stop the bridge, using a bounded wait (DispatchSemaphore with timeout) around a detached task that does not need the main actor.
