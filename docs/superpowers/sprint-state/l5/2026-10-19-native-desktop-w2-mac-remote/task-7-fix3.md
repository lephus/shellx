## Finding (Important, from the fresh Task 7 review; verify it yourself first)
The startup guard can hang forever on a virtual PTY. Where: virtual_pty.rs ~273 (demux `pipe_writer.write_all`), ~382-399 (`VirtualChild::kill`), ~412-418 (`wait`); surface.rs ~2555 (`master` declared), ~2558 (guard declared), ~1785-1792 (guard `Drop` calls `kill()` then `wait()`).
In attach mode the app sends a screen snapshot (up to 1 MiB) right after S. The demux writes it into the in-process `UnixStream::pair` pipe, which holds ~8 KB; the mirror's reader thread starts only later (surface.rs ~2726), so the demux usually sits blocked in `pipe_writer.write_all`. If surface creation fails in between (`try_clone_reader()?`, `Terminal::new()?`, `term.resize()?`, kitty limits, `MouseEncoders::new()?`, `RenderState::new()?`; surface.rs ~2565-2611), the locals drop in reverse order, the guard drops before `master`, the guard calls `kill()` (sends K, shuts the socket down) but the demux is not in a socket read, so `wait()` blocks forever because the pipe's read end (`VirtualMaster.reader`) is only dropped after the guard. Terminal creation runs under `resource_creation_handoff`/`resource_creation_execution` (mux.rs ~14390), and `surface_exited` takes the same locks (mux.rs ~16305), so the hang blocks all later terminal creation and exit handling daemon-wide. Same root cause on shutdown: the reader thread stops on journal close while `master` is alive and the reaper never finishes.

## Fix
Preferred: after hanging up, `VirtualChild::kill` marks the child exited (`self.shared.mark_exited()`): a killed virtual child is gone by definition; final output still drains because the exit publication also waits for the reader's EOF (confirm that in surface.rs `publish_local_exit_if_ready` or equivalent before relying on it); once `master` drops, the demux's blocked write fails with EPIPE and the thread exits. Alternative: keep a clone of `pipe_writer` in `Shared`, `shutdown(Both)` it in kill, and let the demux take/drop it on exit (E must still give the reader EOF). Choose the smaller one that passes the tests below and say why.
Also fix Minor 5 (cheap): when the demux exits because of a protocol error / read error / E, also `shutdown(Both)` its stream so the connection (and the Mac binding) does not linger until the surface drops.
