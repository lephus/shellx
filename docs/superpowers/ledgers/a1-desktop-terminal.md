A7 Task 5 (A5b D4 additive, the A5b executor keeps these): `MuxConnection` gained back-pressure — `pendingBytes` (bytes sent the peer has not taken), `drained` (completes at 0 or on close), `pauseInput`/`resumeInput` (Unix: pauses the socket subscription, so the peer's writes back up in the kernel). `StreamMuxConnection` takes an optional `flush:`; with it (Unix: `Socket.flush`), `send` queues frames and a pump writes and flushes them; `close` lets queued frames go out (bounded 1 s). `MemoryMuxTransport`: a frame is pending until the receiver takes it (held while it paused input), and `close` delivers frames sent before it (the peer closes one microtask later, after them). ⚠ Residual: the Windows pipe passes no `flush`, so `pendingBytes` is always 0 and its input pause buffers in the controller — CliHost back-pressure limits (D24 1000 events, D32 256 KiB unread / 64 waiting) do not engage on Windows until the pipe writer reports completions.
